# onlyoffice-md-autoformat

[English](README.md) | Русский

Плагин ONLYOFFICE Docs: печатаете markdown в docx — получаете форматирование
на лету, как в Google Docs. Работает поверх интеграции Nextcloud + ONLYOFFICE.

## Что конвертируется (as-you-type)

| Ввод               | Результат                     |
|--------------------|-------------------------------|
| `# ` … `###### `   | Heading 1 … Heading 6 (стандартные стили — работают ToC и навигация) |
| `**текст**` + пробел | полужирный (пробел после закрывающего тега — триггер конвертации) |
| `__текст__`        | полужирный                    |
| `*текст*`          | курсив                        |
| `_текст_`          | курсив                        |
| `***текст***`      | полужирный курсив             |
| `~~текст~~`        | зачёркнутый                   |
| `` `код` ``        | Consolas + зелёный текст + серая заливка |
| ` ``` ` + Enter    | открывает блок кода; печатаете код (markdown внутри не конвертируется); закрывающий ` ``` ` + Enter превращает весь блок в стиль «Code Block» (Consolas, заливка) |
| `[текст](https://…)` | гиперссылка                 |

Триггер конвертации — пробел после закрывающего тега, либо Enter/Shift+Enter
(иначе маркер в конце строки остался бы навсегда). Пока триггера нет, маркеры
остаются как есть: `**bold**` в конце строки без пробела не трогаем.

После конвертации текст, который вы печатаете дальше, продолжается форматом
окружающего текста, а не сконвертированного фрагмента (как в Google Docs):
«**test** » превращается в жирный «test», но то, что напечатано после него —
обычное.

## Вставка из Markdown (v0.2.0)

Для целых документов есть второй путь — правый клик в документе →
**Вставить из Markdown** (или откройте окно плагина и перейдите на вкладку
Insert Markdown):

1. Вставьте Markdown в текстовое поле (или нажмите **Открыть .md…** и выберите
   файл; из буфера обмена поле заполняется автоматически, если редактор
   разрешает чтение);
2. Нажмите **Вставить** — содержимое появится в позиции курсора одной
   операцией: настоящие таблицы, списки, гиперссылки, инлайн-код, блоки кода и
   цитаты; одна точка Ctrl+Z.

Работает на vendored [markdown-it](https://github.com/markdown-it/markdown-it)
(MIT, офлайн); сырой HTML в исходном Markdown отключён для безопасности.
Ченджлог на 270 КБ с таблицей на 640 строк и 636 ссылками вставляется за
секунды. Позицию пункта в контекстном меню выбирает редактор (пункты плагинов
группируются); пункт появляется, пока окно плагина запущено (откройте его один
раз во вкладке Плагины — окно можно свернуть, движок продолжит работать). Та же
команда всегда доступна в окне плагина.

Подсказка по набору: строчная конвертация срабатывает на ПРОБЕЛ, введённый
после закрывающего маркера (`*new again* ` → *new again* и пробел), и на Enter
после заголовка или фенса.

Списки (`- `, `1. `) — не дублируем: встроенный AutoFormat редактора создаёт
маркированный список по `- `/`* ` и нумерованный по `1. `/`1) ` (подтверждено
живой проверкой 02.10.2026, Document Server 9.4.0; плагин списки не трогает и
работает внутри элементов списка).

## Установка

### Способ 1 — developer mode (быстрый, без прав на сервер DS)

1. Запустите дев-сервер в репозитории:

   ```bash
   python3 tools/devserver.py 8484
   # Plugin config: http://localhost:8484/config.json
   ```

2. Откройте документ в ONLYOFFICE → DevTools (F12) → вкладка **Console**.
3. В выпадающем списке контекста консоли (сверху, где «top») выберите **frameEditor**.
4. Выполните:

   ```js
   Asc.editor.installDeveloperPlugin("http://localhost:8484/config.json");
   ```

5. Плагин появится во вкладке **Plugins**. После перезагрузки страницы —
   повторить шаг 4 (дев-плагины живут в рамках сессии редактора).

> Если браузер заблокирует mixed content (https-редактор → http://localhost):
> разрешить «Insecure content» для сайта ДС в настройках сайта (иконка замка),
> либо использовать способ 2.

### Способ 2 — на сервере Document Server (постоянный, для всех)

Скопировать папку `plugin/` на сервер DS в `sdkjs-plugins` (имя папки — GUID):

```bash
sudo cp -r plugin "/var/www/onlyoffice/documentserver/sdkjs-plugins/asc.{114F28ED-672A-4640-A6B2-8ED0E9D242CB}"
sudo supervisorctl restart all   # или: docker restart <DS-контейнер>
```

(Docker: `docker cp plugin <контейнер>:/var/www/onlyoffice/documentserver/sdkjs-plugins/asc.{…}`
и перезапустить контейнер.) Обновить страницу с редактором.

### Способ 3 — zip (там, где Plugin Manager позволяет загрузку)

`dist/md-autoformat.zip` → **Plugins → Manage plugins → Upload a plugin**
(доступно не во всех сборках веб-версии).

## Управление

- Чекбокс в окне плагина — включить/выключить (запоминается в браузере).
- **Convert whole document** — разовая конвертация всего документа
  (удобно после вставки текста с markdown-разметкой).
- **Ctrl+Z** — отменяет конвертацию целиком (одна запись истории = одна конвертация).

## Защита от ложных срабатываний (гварды)

- конвертация запускается пробелом после закрывающего тега (или Enter/
  Shift+Enter в конце строки): `**bold**` без триггера остаётся markdown,
  `**bold** ` — конвертируется;
- `_` внутри слова не работает: `snake_case_name` остаётся как есть;
- `5 * 3 * 2` — не курсив (маркер после цифры);
- контент не может начинаться/заканчиваться пробелом: `* пробел *` — не конвертируется;
- внутри Code Block markdown не конвертируется, кроме закрывающего ` ``` `;
- ссылка конвертируется только для `http(s)://`, `www.`, `mailto:`, `ftp://`.

## Co-editing

Плагин трогает только абзац под курсором локального пользователя, делает
конвертацию идемпотентной (маркеры исчезают) и ограничивает частоту.
Каждый участник управляет своим плагином независимо.

## Ограничения (0.1.1)

- движок живёт в окне плагина: после переоткрытия документа плагин нужно
  открыть заново (фоновый автостарт — в roadmap);
- «Convert whole document» пропускает абзац, если он изменился извне во время
  прогона (безопасно, повторный прогон добьёт его);
- спан, пересекающий мягкий перенос внутри, конвертируется, но
  форматирование может распространиться на весь абзац (поведение редактора
  для диапазонов, содержащих перенос);
- таблицы markdown не поддерживаются;
- незакрытый блок кода (один ` ``` ` без пары) остаётся текстом как есть;
  строки вида ` ``` текст` (маркер + текст в той же строке) движок не трогает;
- ссылки `[text](url)` создаются обходным путём: плагин выделяет
  сконвертированный фрагмент и вставляет поверх него `<a>`-фрагмент через
  PasteHtml (SDK-метод `AddHyperlink` молча не работает внутри песочницы
  плагина — проверено на ONLYOFFICE Docs 10.0.2). Если сборка ограничивает
  PasteHtml, текст конвертируется, а сама гиперссылка может не появиться
  (движок пишет об этом в лог).

## Изменения v0.1.2 → v0.1.3

- исправлено (баг «конверсия без ввода»): `GetText()` живого редактора ВСЕГДА
  заканчивается меткой абзаца `\r\n` — даже пока пользователь печатает.
  Сырой текст попадал в правила, `closerOk` считал маркер в конце абзаца
  завершённым, и `**test**` конвертировался сразу после набора последнего
  символа (без пробела и без Enter). Теперь метка срезается до планирования;
  конверсия по Enter работает через отдельный сигнал: событие пустого абзаца
  (см. ниже);
- добавлено: Enter после готового маркера конвертирует ПРЕДЫДУЩИЙ абзац.
  Раньше «Enter-триггер» был артефактом той самой метки `\r\n`; теперь движок
  ловит событие редактора о пустом абзаце (флаг `pendingEnter`), читает
  предыдущий абзац и применяет план к нему по индексу. Клик мышью в пустой
  абзац (поллинг) конверсию не вызывает;
- исправлено (баг «курсор в середину слова»): позиция конца абзаца считалась
  как `длина - 2` и для `**test** ` (7 символов с меткой) давала позицию
  перед пробелом — каретка вставала в «test| ». Теперь берётся полная длина
  `GetText()`, каретка встаёт после завершающего пробела («test |»);
- исправлено: guard удалений зависел от `GetInternalId()`, который на части
  сборок DS возвращает null — Backspace снова провоцировал конверсию. Guard
  теперь опознаёт абзац по ИНДЕКСУ из neighbour-скана (а не по id);
- исправлено: neighbour-скан (индексы соседних абзацев, fence-пары, Enter)
  молча падал в песочнице редактора — константа `MARKDOWN_CHARS` не была
  доступна в теле `callCommand`. Константа вплетается в команду так же, как
  ruler-хелперы; без этого fence-закрытие и Enter-ветка не работали вовсе;
- исправлено: событие Enter могло теряться между занятой цепочкой и
  фингерпринт-дедупом пустого абзаца (пустой фингерпринт константен, цепочка
  отбрасывалась до планирования) — `pendingEnter`-цепочка с пустым текстом
  проходит дедуп;
- исправлено (баг «Ctrl+Z → снова форматирование»): guard отмены v0.1.2
  запоминал исходный текст в одной глобальной ячейке, и собственное
  перечитывание абзаца сразу после конверсии («**test** » → «test ») выглядело
  как пользовательская правка — guard разоружался за доли секунды, и Ctrl+Z
  конвертировал вернувшийся маркер заново. Теперь guard хранится по абзацам:
  `lastConverted[индекс] = {from, to}` — `from` (исходный маркер) блокирует
  повторную конверсию, `to` (результат нашей конверсии, читается после мутаций)
  не даёт движку разоружить guard при собственном перечитывании. Работает и для
  Enter-пути (конвертированный соседний абзац читается по индексу), и для
  «Convert whole document» (результаты фиксируются одной командой чтения);
- добавлены юнит-тесты контракта движка: текст без завершающего пробела не
  конвертируется, с пробелом — конвертируется, Enter-ветка пере-добавляет
  виртуальную метку `\r\n` и конвертирует, незакрытый маркер не трогается;
- исправлено (баг «`**text some * text**` не конвертируется»): regexp bold
  использовал ленивый `.+?` до первого закрывающего `**` — внутренний `*`
  ломал спарсинг. Теперь `**` ищет до конца слова и внутренний одиночный `*`
  не мешает (проверено живо и юнит-тестами);
- исправлено (баг «курсор прыгает в конец строки»): после конверсии в середине
  строки каретка вставала в конец абзаца. Теперь движок возвращает якорь
  (текст внутренней части) и отдельной командой ставит каретку сразу ПОСЛЕ
  конвертированного слова — «test `code` text» → каретка после «code»;
- исправлено (скрытый баг форматирования): удаление маркеров оставляет в модели
  ПУСТЫЕ СЛОТЫ, и диапазон `GetRange(openerAt, openerAt+len)` захватывал слот +
  внутренний текст минус последний символ — жирность/курсив ложились на 1
  символ меньше (и каретка вставала на 1 раньше). Диапазон теперь ищется по
  точному тексту внутренней части (GetText пропускает слоты) — проверено живо:
  весь «text some * text» жирный;
- исправлено (баг «``` оставляет пустую строку кода»): блок кода конвертируется
  ОДНОЙ командой редактора — маркеры удаляются, строки контента получают
  стиль Code Block, маркерные строки — Normal (невидимые, как закрывающий
  маркер). Удалить пустые маркерные абзацы целиком SDK не даёт (удаление знака
  абзаца пустого абзаца игнорируется, `p.Remove()`/`doc.RemoveElement` не
  работают в песочнице) — строка исчезает визуально;
- исправлено (баг «Ctrl+Z возвращает одну строку»): SDK закрывает точку
  истории ПОСЛЕ КАЖДОЙ команды редактора, поэтому пошаговая конверсия блока
  давала по точке на строку. Весь fence-блок теперь мутируется в одной команде
  с одним `CreateNewHistoryPoint()` — Ctrl+Z возвращает всю md-вёрстку блока
  разом (подтверждено живо);
- исправлено (баги «`[text](http://…)` / `[text](example.com)` не ссылка»):
  правила теперь распознают ссылку и с scheme, и с голым доменом (однословные
  `(note)` остаются текстом), маркеры удаляются и вызывается `AddHyperlink`
  отдельной командой. Ограничение: в веб-сборке TrueConf `AddHyperlink`
  игнорируется песочницей (см. «Ограничения»), движок проверяет модель и
  пишет об этом в лог.

## Изменения v0.1.3 → v0.1.4

- добавлены подпункты **Запустить / О плагине** у кнопки плагина (как у

  (локализовано по `?lang=` из URL плагина). Окно «О плагине»: название,
  версия, описание, автор Димитрий Зуйков, Труконф. При dev-установке
  фоновую вариацию нужно запустить вручную: `asc_pluginRun(guid, 0, "")`;
  при установке zip через менеджер плагинов она стартует автоматически;
- исправлено (баг «первая строка ``` остаётся пустой внутри кода»): оба
  маркерных абзаца теперь УДАЛЯЮТСЯ ПОЛНОСТЬЮ со смещением текста — первая
  строка контента встаёт на место открывающего ```, закрывающий ```
  сливается с пустым абзацем под блоком (каретка остаётся в нём). Удаление
  знака абзаца работает, только пока в абзаце есть текст; для самого
  последнего абзаца документа SDK его игнорирует — такой маркер остаётся
  невидимой Normal-строкой (фолбэк). Работает и в «Convert whole
  document»: блоки конвертируются отдельным проходом снизу вверх, чтобы
  удаления не сдвигали индексы остальных элементов;
- Ctrl+Z по-прежнему возвращает весь блок одной командой — включая
  удалённые маркерные абзацы (одна точка истории на блок);
- окно «О плагине» локализовано целиком: в английской версии вместо
  «Труконф» — «TrueConf»;
- добавлена собственная кнопка закрытия ✕ в окне «О плагине» и в окне
  конвертера: хром окна DS не закрывает PluginWindow-дочерние окна
  (крестик в заголовке — no-op, ограничение сборки), страница закрывает
  себя сама через `CloseWindow` со своим windowID.

  последний символ («*тест т*» → «тест *»), а курсор мог прыгать перед
  словом. Маркеры теперь ищутся в живом тексте линейно (первое совпадение
  слева — опенер, следующее строго после него — клозер), мутации идут от
  правого края;
- исправлено: потерянный редактором ответ (callCommand) мог на минуты
  блокировать движок в свёрнутом окне плагина — цепочка отменяется по
  таймауту 60 с;
- исправлено: после конверсии курсор прилипал к границе форматирования и
  оказывался ПЕРЕД словом («тест текст *курсив*» → курсор перед «курсив»)
  — после конвертации курсор явно возвращается в конец абзаца;
- исправлено: Ctrl+Z после конвертации приводил к повторной конвертации
  вернувшегося текста — движок запоминает исходный текст конвертации и не
  трогает его, пока он не изменится (логика Google Docs);
- исправлено: удаление символов могло провоцировать конвертацию («*code*»
  → удалили символ → «*cod*» форматировался) — текст, ставший короче, не
  конвертируется;
- добавлено: `***текст***` — полужирный курсив (приоритетнее `**` и `*`);
- добавлено: блок кода теперь оформляется по-гдоковски: открывающий ` ``` `
  ничего не делает, пока не введены закрывающий ` ``` ` и Enter — после этого
  весь блок (всё между маркерами) становится стилем «Code Block», оба маркера
  удаляются; внутри незакрытого блока markdown не конвертируется; ` ``` текст`
  и одиночный ` ``` ` без пары остаются как есть;
- добавлено: инлайн-код — моноширинный зелёный текст с серой заливкой
  (в середине строки тоже).

## Изменения v0.1.0 → v0.1.1

- конвертация стала атомарной: чтение текста и мутация — в одном шаге с
  перепроверкой, устаревшее чтение больше не может повредить документ;
- позиции считаются по абзацу, а не через `doc.Search` — раньше одинаковый
  спан в другом абзаце документа форматировался там, а под курсором оставался
  (и движок мог заклинить в бесконечном ретрае, «голодая» остальные конверсии);
- спан с мягким переносом внутри (`**a` + Shift+Enter + `b**`) конвертируется
  (раньше — вечный цикл `apply skipped`);
- неудачная конверсия уходит в cooldown 4 с вместо бесконечного ретрая;
- Enter/Shift+Enter сразу после закрывающего тега — триггер конверсии;
- внутри Code Block markdown не конвертируется, повторный ` ``` ` корректно
  закрывает блок;
- исправлена граница ссылки (закрывающая `]` не съедалась);

`callCommand`, `plugin/scripts/ui.js` — окно настроек.
